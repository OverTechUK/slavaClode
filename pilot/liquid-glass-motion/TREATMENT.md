# Treatment · «Стекло открывает то, что под капотом»

Статус: кандидат для пилота. Бренд-канон не меняется, DESIGN.md не трогали. Это немые motion studies: без VO и без музыки.

## Общая логика
Стекло здесь — инструмент разбора, а не украшение. Оно появляется, когда нужно что-то показать: увеличить деталь, подписать слой или обозначить связь. После этого стекло уходит или остаётся меткой. Ритм у всех проб один: вход 0.5–0.6 c с easeOut, перемещение около 1.1 c с easeInOut, затем hold не меньше 2.5 c и выход 0.4–0.6 c. Постоянных вращений, bounce и бликов без причины нет. Блик стоит на скруглённом крае, свет падает сверху слева.

**Материалы.** Все материалы авторские: процедурный «демо-кадр» с фоном, фигурой, контровым светом и титром «ВЕЧЕРНИЙ СВЕТ». Он рисуется кодом в `src/components.js → demoLayers()`. Скринкастов, чужих кейсов и материалов работодателя нет. Везде, где виден кадр, стоит плашка «ДЕМО-КАДР · ГРАФИЧЕСКАЯ СХЕМА».

## 1 · Линза разбора (10 c)
- **Что видит зритель.** Сначала заголовок «ПОЧЕМУ КАДР / РАБОТАЕТ» и Caveat «разберём». Затем стеклянная линза подъезжает к плечу фигуры и увеличивает контровой свет. Появляется метка «Контровой свет — отделяет фигуру от фона». Потом линза уходит.
- **Что понимает.** Конкретная деталь кадра даёт конкретный эффект.
- **Такты.** 0.1 заголовок → 0.4 кадр → 1.6 вход линзы → 2.2–3.4 движение к детали → 3.2–3.8 нарастает увеличение → 3.8 метка → hold до 7.6 → 7.9–8.5 линза уходит → 8.5–10 исходная картинка.
- **Резерв.** `--optics 0`: плоская выделяющая панель без преломления.

## 2 · Под капотом (13 c, главный)
- **Что видит.** Цельный кадр раскладывается по глубине на слои «Исходник / Маска / Эффект / Титры». Стеклянные метки по очереди подсвечивают каждый слой, остальные приглушены. Затем слои собираются обратно, и следует hold результата с подписью «схема слоёв · не трекинг реального видео».
- **Что понимает.** Как из плана, маски и эффекта собирается итоговый кадр.
- **Такты.** 0.1 заголовок → 0.5–2.4 собранный кадр → 2.4–3.8 разнос → 3.4 метки → 4.6–9.0 подсветка слоёв по 1.1 c каждый → 9.2–10.6 сборка → 10.6–13 hold с подписью.
- **Резерв.** `--optics 0`: разноса нет, слои включаются последовательно на месте, метка плоская.

## 3 · Один исходник → три подачи (10 c)
- **Что видит.** Миниатюра демо-кадра разветвляется по стеклянным связям в три композиции с хуками «ПОЧЕМУ СВЕТИТСЯ?», «ДО И ПОСЛЕ», «ГДЕ ОШИБКА?». Над каждой стоит метка изменения, Caveat «меняем хук». Затем импульсы бегут обратно по связям к источнику и появляется метка «общий исходник».
- **Что понимает.** Это одна съёмка, у которой меняется только подача. Обещаний конверсии или автоматизации нет.
- **Такты.** 0.8 источник → 1.8–3.0 растут связи → 2.2–3.6 миниатюры вылетают из источника → 3.2 метки → hold до 6.8 → 6.8–7.8 импульсы назад и метка «общий исходник» → hold до 10.
- **Резерв.** `--optics 0`: обычные линии связи и плоские метки.

## Путь реализации
Сначала проверил среду. Есть Chromium (Playwright 1.56) с WebGL через SwiftShader, ffmpeg 6 с libx264, Node 22. Remotion, Three.js и AE не установлены и не используются.

Сцена рисуется в три слоя:
1. `under` — Canvas2D: фон и кадр.
2. Проход стекла — WebGL-шейдер: искажает `under` в каждом кадре по нормали скруглённого края, добавляет увеличение, RGB-кайму, блик и тень.
3. `over` — резкий текст поверх стекла.

Рендер покадровый и детерминированный. Время берётся только из номера кадра. Кадры передаются в ffmpeg через pipe.
